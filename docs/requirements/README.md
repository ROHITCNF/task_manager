# Requirements

Functional and non-functional requirements for the task management UI.

## What goes here

- Product requirements / feature specs (e.g. task CRUD, filtering, status workflow)
- User stories and acceptance criteria
- Non-functional requirements (performance, accessibility, browser support)
- Scope notes: what is in and out for each milestone

## Conventions

- One file per feature or requirement area, e.g. `task-board.md`
- Give each requirement a stable ID (e.g. `REQ-001`) so design docs and ADRs can reference it
